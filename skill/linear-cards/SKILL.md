# 写给没跟进过程的人

标题用同事能认出来的叫法，例如「核对评测帧率」。开头说明要做到什么和怎么判断做完。正文用短段落写当前结果、仍卡在哪里，以及接下来谁做什么。结单时写结论，附上能点开的证据。图片、视频等关键产物可用 `linear-app attach` 放进卡里。机器日志、编排单号、内部 JSON 和长表格留在原处，有需要时给链接。

## 状态跟着实际进展走

- **Todo**：确定还要做，尚未开始，或本轮已停下来等续派。写明停在哪和接手人。
- **In Progress**：有人在做，或仍有后台任务要收结果。阶段变化时更新正文。
- **Done**：卡的目标已经达成，证据和结果上卡，相关活已收尾。长期卡也按这个标准。关父卡前先核实未关闭的子卡，避免 Linear 连带改态。
- **Canceled**：决定不做了或并入另一件事。第一行写原因，或写「并入 <REDACTED_ID>」。合并保留原卡。
- **Human Intervention**：只有童成卓本人能解除的阻塞，例如批准一笔采购或给独有的授权。常驻卡用于持续运行的服务。

## 需要童成卓做什么

建卡不订阅童成卓，普通评论不提及他。真需要他关注、决定或操作时，用 `linear-app ask TCZ-n '一句话'` 在原卡提及一次。第一句直接给动作和选项，例如「请决定先买一块测试板还是等新批次。建议先买一块，周五前可开测。」需要他本人处理、其他人无法继续时加 `--blocking`，卡进入 Human Intervention。他回复后把结论写回卡。

常规验收和完成汇报写在卡上。`linear-app ask --accept` 只记验收材料，不改状态、不发提醒。确实需要他对结果做选择时问具体选择，例如是否批准发布。进展通过 `amb progress` 或 `linear-app progress` 写回正文。已有事项优先写回原卡。有独立交付、自己的状态，而且有人需要单独追踪时才开子卡，比如可独立验收的评测数据集。重跑、子步骤、收结果放回原卡。
