# 综合：Ambition 路由/对齐 skill 设计
模型：fable.md = Claude CLI `--model fable`（VPS，自报 claude-fable-5-2，Fable 5.2）；astra.md = Codex `gpt-6.2-astra`，effort low，read-only（VPS，codex-cli 0.170.0）。各开新会话，同一份题目。dev 上 Claude 的 fable 别名是 claude-fable-5-1，不是 5.2，所以没用 dev。

## 共识
- Ambition 只做：听懂 → 写任务单 → 收结论回话；不读日志、不转述、不盯进度。
- 协调由脚本/调度器负责，模型间只通过文件交接（任务单 / 结论 / 验收记录），不共享聊天上下文。
- 验收由脚本或独立复核执行，执行方自报不算完成；证据必须是原始输出，且对应本次产物版本。
- Sol medium 为默认执行者；Opus low 做复核/文字类；Astra/Fable 只在目标模糊、跨系统、高风险或已失败时规划，不执行。
- 聊天只在需要决定、阻塞、终态、实质变化时说；Linear 只覆写固定状态块、不评论；飞书一行 FYI；无变化全静默；机器不可达≠关机、不计失败、不触发升级。
- cron 全脚本，正常路径不调模型；出错先确定性修复，再 AI，带限时、allowlist、冷却和熔断。
## 分歧
- 流程档位：Fable 给明确 L1/L2/L3 触发条件和默认 3 次尝试 + 时限（估值）；Astra 不定档，按风险触发，强调“一次能确定性验收的不加模型”。
- 调度实现：Fable 用 job 目录 + run-job.sh/watch-jobs.sh（轻）；Astra 用 VPS 上 SQLite 持久化调度器 + 租约（重）。
- 交接物格式：Fable 用 markdown（ticket.md/result.md，便于人读）；Astra 用 yaml/json 带 task_id、attempt、verdict（便于机器校验）。
- 聊天时机：Fable 固定四时刻（含接单一句话）；Astra 更克制，接单只说“已接单”，不主动发里程碑。
- 升级：Fable 失败次数硬上限；Astra 强调“无新证据不重派”、租约过期、旧尝试不能提交终态。
## 建议
以 Fable 为骨架（具体、轻量、马上能落地：目录 + shell 脚本 + 四时刻），吸收 Astra 的：json 结论/验收记录字段（task_id、attempt、版本、逐条 pass/fail/unknown）、租约/尝试编号防重复领取、“手动成功≠验收，需等定时验收”、“接单回执只能说已接单，领取后才说已开始”。SQLite 调度器暂不上，job 目录够用，量大再升级。

## 规则清单草稿（可写入 skill）
1. Ambition 动作白名单：写任务单并 dispatch；读 result 与 status；聊天发言；向用户提一个决策问题。想开日志/源码或连续跑超过 3 条命令 → 停手改派单。
2. 先选机器（活在哪就在哪：<REDACTED_PLATFORM>→dev，运维/cron→VPS，Mac 专属→Mac，其余→box），再选角色。
3. 默认 Sol medium 执行；文字类与独立复核用 Opus low；目标模糊/跨机器/交付物>3/不可逆或生产风险/已失败两次 → Astra/Fable 只出计划与子任务单。
4. 档位：L1 执行+脚本验收；L2 再加异模型复核（上线改动、验收非纯命令）；L3 规划→执行→验收→复核；拿不准取 L2。
5. 任务单必含：用户原话、解释与假设、范围（可改/不可动）、带编号的验收命令、预算与截止。规划方可加验收，不可删或放宽。
6. 验收命令由 runner 执行并落盘；终态 done 只能由 runner 写，执行方只能“申请完成”；复核只读，只看任务单、diff、evidence。
7. 结论文件固定字段：status、summary、evidence（指针）、unverified（必填）、needs_human；json 化并含 task_id、attempt、产物版本。
8. 升级链由脚本执行：同级重试带失败证据 → 规划重写 → blocked 交人；每次失败写 attempts/n.md；原因相同连续两次跳过同级；无新证据不原样重派；心跳超时即杀并计一次失败；总尝试上限 3、每任务有截止。
9. 缺权限/凭证、要用户取舍、不可逆操作 → 不升级，直接交人。
10. 机器不可达 → waiting_host，脚本重试，不计失败，只说一次“上线后自动开始”；SSH 不通不得推断“已关机”。
11. 聊天只在：接单（一句：理解+派给谁+假设）、完成（结论+证据+未验证项）、阻塞（一个问题+推荐项）、实质变化。其余静默；发前自检“用户看完会不会有不同行动”。
12. 状态陈述三类：已验证（带证据指针/时间）、执行方自报未复核（原样标注）、不知道（说明已派谁查）。超 30 分钟的状态带“截至 HH:MM”。
13. Linear：issue 描述内固定状态块（状态/现在/证据/等谁/更新），由脚本整体覆写，不评论。
14. 飞书：脚本发，≤40 字一行，仅完成/阻塞/线上故障，按任务ID+状态去重。
15. cron：checks/*.sh + fixes/*.sh + run-checks.sh；首次失败等下一轮；连续2次失败先确定性修复；仍失败自动生成任务单（验收=该检查本身）调用 AI，限 20 分钟、allowlist、同一检查 6 小时最多 2 次；1 小时翻转>3 次熔断上报；巡检自身写心跳、由 box 监控；AI 修好后沉淀为 fixes 候选。
16. 防护：Ambition 越权干活（统计白名单外命令，不给 dev 仓库写权限）；执行方改验收/测试文件 → diff 标出强制复核；理解错 → 复核清单第一条“是否回应原话”；无声失败 → 截止到点强制 failed 并唤醒。
